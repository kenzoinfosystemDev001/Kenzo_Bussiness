## 2. Database migration

`20261116000000_vendor_management` (additive only — no changes to Phase 01 tables except relations):

- Tables: `vendor`, `vendor_contact`, `vendor_bank_account`, `vendor_bank_change_request`, `vendor_document`, `vendor_status_history`.
- Composite FKs `(company_id, vendor_id) → vendor(company_id, id)` so child rows can never point at another company's vendor.
- Partial unique indexes: one live vendor per GSTIN per company; one ACTIVE bank account per vendor; one pending bank change per vendor; one primary contact per vendor.
- CHECK constraints: GSTIN format, GST-type/GSTIN consistency, payment terms 0–365, currency, MSME number, PAN field consistency, IFSC format, routing code presence, fingerprint format, document version ≥ 1, expiry ≥ issue date, verified ⇒ verifier + timestamp.
- Append-only trigger on `vendor_status_history`.
- `down.sql` provided; migration gate passes for both migrations (up → drift-free → down → up).
- Applied to the Neon database with `prisma migrate deploy`.

## 4. Security controls specific to Phase 02

Maker-checker for bank changes and onboarding; creator exclusion; uploader ≠ verifier; activator ≠ creator; encrypted + fingerprinted restricted identifiers; masked responses (no ciphertext or fingerprints in any API payload); audited reveals with reasons; full numbers never written to logs or audit; private documents readable only via vendor permission + signed URL + session; cross-company access returns 404 on every vendor endpoint; duplicate checks never cross tenants.

## 7. Known limitations

- Transactional relations in Vendor 360 and four performance indicators depend on Phases 3–5 and are displayed as unavailable until those modules exist.
- Legal/tax identity changes after approval require a new vendor record (no re-approval flow for identity amendments yet).
- For GST-registered vendors the PAN is visible through the GSTIN by law (TD-21).
- Document malware scanning and S3 storage are inherited Phase 01 limitations.
- Expiry scan runs in-process every 6 h (`VENDOR_EXPIRY_SCAN_MS`); a dedicated worker comes with BullMQ.
